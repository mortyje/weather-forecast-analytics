# Архитектура

## Сбор и доставка

Python получает оперативные прогнозы Open-Meteo и почасовые наблюдения Meteostat. Отдельные команды загружают архивные выпуски ECMWF IFS и наблюдения за прошедший период. В `control.station_assignments` хранится станция, выбранная для каждого города. События наблюдений содержат станцию и фактическое время её назначения.

Kafka принимает прогнозы в `weather.forecasts.raw`, а наблюдения — в `weather.observations.raw`. Spark запускает по одному потоку на топик. В Raw сохраняются исходное сообщение, время его загрузки и ключ `(topic, partition_id, offset_id)`. Повторная запись с тем же ключом пропускается через `ON CONFLICT DO NOTHING`.

Spark хранит прогресс каждого потока в отдельном каталоге тома `spark_checkpoints`. С сохранённым checkpoint поток продолжает обработку с записанных смещений. Настройка `startingOffsets=earliest` используется при первом запуске потока без checkpoint.

## Хранилище

Staging выделяет поля из событий и разделяет оперативные и архивные прогнозы. Intermediate разворачивает почасовые массивы. Core хранит историю оперативных снимков, назначения станций и уникальные почасовые наблюдения. При повторной доставке измерения сохраняется последняя версия для пары `(station_key, observed_at)`.

Большинство моделей Core используют инкрементальный `MERGE`. Архивные выпуски идентифицируются по городу, модели и времени инициализации. Core выбирает последнюю копию выпуска и перестраивает его почасовые данные по выбранной версии. Витрины пересчитывают сопоставления и MAE, RMSE и Bias с учётом исправленных наблюдений и назначений. ## Оркестрация и визуализация

Airflow собирает оперативные прогнозы каждые три часа и наблюдения ежедневно в 07:15 UTC. DWH DAG запускается каждые три часа на 30-й минуте UTC. Он фиксирует диапазоны Kafka offsets, ждёт записи соответствующих событий в Raw и запускает `dbt run` и `dbt test`.

Grafana читает схему `dm` через роль `grafana_reader`. Источник и дашборды загружаются из файлов при запуске. Витрина `dm.pipeline_freshness` показывает время последнего сбора и последней загрузки оперативных событий.

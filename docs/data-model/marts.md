# Витрины точности прогнозов

В схеме `dm` находятся измерения `dim_locations` и `dim_stations`, таблица фактов `fact_forecast_accuracy` и агрегат `forecast_accuracy_by_horizon`. dbt перестраивает эти таблицы целиком, поэтому исправленное измерение из Core будет учтено при следующем расчёте.

## Сопоставление прогнозов и измерений

В `fact_forecast_accuracy` одна строка на пару `(snapshot_id, forecast_for)`. Горизонт — число часов между началом часа получения прогноза (`collected_at`, усечённое до часа в UTC) и целевым временем `forecast_for`. Горизонт 0 соответствует прогнозу на час сбора. Прогнозы на более ранние часы исключаются.

Станцию выбираем по назначению, действующему на целевой час. Начало интервала `valid_from` включается, конец `valid_to` исключается. Если `valid_to` равен `NULL`, назначение действует с `valid_from` без верхней границы. Наблюдение ищем по `station_key` и точному совпадению `observed_at` с `forecast_for`.

История назначений Core восстанавливается из событий Meteostat. Если у старого прогноза отсутствует подтверждённое назначение, прогноз сохраняется со `station_key = NULL`. Отсутствие наблюдения отражается в `has_observation = false`. Если наблюдение есть, но отдельный показатель пропущен, ошибка по этому показателю остаётся `NULL`. Ошибка также равна `NULL`, если значение прогноза отсутствует.

Ошибка определяется как **прогноз − факт**. Положительное значение показывает завышение, отрицательное — занижение. Прогноз относится к координатам города, а измерение — к координатам выбранной станции поблизости. При интерпретации ошибки учитывайте пространственное различие этих точек.

## Метрики по горизонту

В `forecast_accuracy_by_horizon` одна строка на `(location_id, horizon_hours, metric_name)`. Метрики рассчитываются отдельно для температуры, влажности, осадков и скорости ветра.

`forecast_count` показывает число прогнозных строк в группе, `comparison_count` — число пар с обоими значениями. В формулах $e_i$ обозначает ошибку, а $n$ — число полных пар.

| Метрика | Формула |
|---|---|
| MAE | $\frac{1}{n}\sum_{i=1}^{n}\lvert e_i\rvert$ |
| RMSE | $\sqrt{\frac{1}{n}\sum_{i=1}^{n}e_i^2}$ |
| Bias | $\frac{1}{n}\sum_{i=1}^{n}e_i$ |

При `comparison_count = 0` все три метрики остаются `NULL`. Результаты округляются до трёх знаков после запятой и выражаются в единицах исходного погодного показателя.

## Архивные прогнозы ECMWF IFS

Архивные выпуски поступают из Open-Meteo Single Runs API. В `core.archive_forecast_runs` одна строка на `(location_id, model_id, model_run_at)`. При повторной загрузке dbt сохраняет прежний `archive_run_id`, выбирает последнюю копию события и заново строит `core.archive_forecast_hours` по выбранным версиям. В почасовой таблице и в `dm.fact_archive_forecast_accuracy` одна строка на `(archive_run_id, forecast_for)`.

Модельный горизонт — число часов между инициализацией модели (`model_run_at`) и целевым часом (`forecast_for`). Время хранится в UTC. Core сохраняет горизонты от 0 до 168 часов включительно в пределах данных выпуска. Витрина анализирует горизонты от 6 до 168 часов. Время инициализации предшествует публикации, поэтому порог в 6 часов приближённо учитывает задержку. Сравнение показывает ретроспективное качество прогнозов по модельному горизонту. Фактическая доступность конкретного выпуска для пользователя могла отличаться. [Open-Meteo Single Runs API](https://open-meteo.com/en/docs/single-runs-api)

Для целевого часа сначала ищем назначение станции в интервале `[valid_from, valid_to)` (`historical_assignment`). Если его нет, используем последнее известное назначение города (`retrospective_fallback`). Поэтому смена станции может изменить результаты ретроспективного сравнения. Если назначений нет (`no_station`), прогноз сохраняется без факта. Наблюдение подбирается по станции и точному совпадению целевого часа. Измерение относится к координатам станции, а прогноз — к координатам города. Часть расхождения может объясняться расстоянием между ними.

В `dm.archive_accuracy_by_horizon` одна строка на `(location_id, model_id, model_horizon_hours, metric_name)`. MAE, RMSE и Bias рассчитываются по парам со значениями прогноза и измерения. Когда полных пар нет, `comparison_count` равен нулю, а метрики остаются `NULL`. Дашборд **Historical Forecast Accuracy** рассчитывает температурные метрики по строкам фактов за выбранные город и период. Для временного ряда используется самый поздний подходящий выпуск на каждый целевой час.
